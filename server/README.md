# Local composition and Tidal bridge

The web app talks only to a local Express server bound to `127.0.0.1:4318`. The server invokes each user's installed Codex CLI using that computer's own **ChatGPT OAuth login**. `npm run doctor` checks the executable, required command-line capabilities, and authentication before use. `npm run login` delegates sign-in to the installed CLI. No OAuth credential is opened, copied, sent to the browser, or stored in this project.

`CODEX_BIN` explicitly chooses one executable. Otherwise discovery checks `codex` on PATH and, on macOS, the usual ChatGPT/Codex application locations. `--version`, `exec --help`, and `login status` distinguish missing installations, incompatible command-line options, logged-out users, API-key authentication, and failed or timed-out probes. API-key login does not satisfy this app's ChatGPT OAuth requirement. Raw login output and executable paths are not exposed by the HTTP status response.

Both `npm start` (built browser audio) and `npm run start:native` (built native Tidal/SuperDirt) serve the client and API on `http://127.0.0.1:4318`. All public launchers require Codex and OAuth before starting the service. Build with `npm run build` first. Development uses Vite on port 5173; `npm run dev:native` also starts the native engine. The server only serves the built `dist/` directory in release mode, never the repository, `.runtime/`, or credential directories.

`codex exec --ignore-user-config --ephemeral --sandbox read-only` runs in a new temporary directory with a JSON output schema. Ignoring user configuration avoids loading unrelated MCP integrations; the CLI retains its saved authentication. `CODEX_MODEL` can explicitly select a model; otherwise the CLI chooses its default. The prompt asks Codex to compose all eight layers from preceding symbolic note/rhythm/mix context. The browser receives no claim that the model heard an audio recording.

The initial request buffers a full eight-layer score so model latency cannot disturb two-cycle entrances. Optional next-layer requests use the current score as context. Only one generation runs at a time. Disconnecting the request or stopping its playback session cancels the child process group; the default deadline is 120 seconds. Generation errors remain errors; the browser does not substitute locally composed music. Responses are validated independently of the schema; incoming Haskell strings are discarded, and trusted `loopToTidal` code renders bounded note events. The server never evaluates raw model code or invokes a shell.

`shared/profiles.ts` defines eight genres: deep house, techno, UK garage, drum and bass, trip hop, ambient, electro, and dub. Each has distinct tempo ranges, scales, drum kits, pitched instruments, and composition directions. A score includes a canonical `profile` with genre, BPM, tonic, scale, key, and assigned instrument names. Major, minor, Dorian, and minor pentatonic scales are supported where appropriate. Automatic generation avoids repeating the last successfully generated genre. Codex receives these constraints and writes genre-specific rhythms, harmony, and note articulation; refinements preserve the established profile. Tempo is validated from 60 to 180 BPM, and all generated sustain values use that score's tempo.

## API

| Endpoint | Request / response |
| --- | --- |
| `GET /api/session` | `{epoch}`; read immediately before an explicit Play claim |
| `POST /api/session/claim` | `{sessionId:UUID,revision,expectedEpoch}` → `{ok:true,epoch}`; revoke the old owner and wait for silence |
| `POST /api/session/stop` | `{sessionId,revision,action:"pause"\|"reset"}` → `{ok:true,epoch,cycle?}`; priority cancellation |
| `GET /api/status` | `{codex:{available,authenticated,ready,authMethod,version,reason,action,busy},tidal:{enabled,available,running,superDirtAvailable,reason}}`; refreshes local Codex detection |
| `POST /api/compose` | `{seed?,genre?:GenreId\|"auto",previous?:Composition}` → `Composition` with profile, eight loops, and `source:"codex"` |
| `POST /api/next` | `{loops,id,profile,seed?,bpm?,key?}` → one Codex `Loop`; tempo/key must match profile |
| `GET /api/samples/:bank/:index` | The indexed actual Dirt-Samples WAV file from a whitelisted bank |
| `POST /api/tidal/transport` | `{action:"start",loops:allEight,bpm}` → `{ok:true,startAt,cycle:0}` |
| `POST /api/tidal/transport` | `{action:"pause"\|"resume"\|"reset",loops?,bpm?,cycle?,fullScore?}` → `{ok:true,cycle,startAt?}` |
| `POST /api/tidal/play` | `{loop,bpm?,cycle?}` → `{ok:true}`; replace a queued layer |
| `POST /api/tidal/trigger` | `{loop,bpm?,velocity?:0.05..1}` → `{ok:true}`; immediately play the first note/chord cluster |
| `POST /api/tidal/transition` | `{loops:allEight,bpm,durationSeconds?:1..20}` → `{ok:true,startAt,durationSeconds,cycle:0}`; default fade 8 seconds |

The browser claims a session only after explicit Play. Every subsequent composition, next-layer, and native POST includes that `sessionId` and `revision`. Every Play, Stop, and Refresh increases the browser revision. Claim compares `expectedEpoch` with the last `GET /api/session` response; a delayed claim cannot reclaim ownership after a newer claim or stop. Stop invalidates the lease synchronously, aborts registered Codex subprocesses and queued native work, immediately mutes native output, then acknowledges after in-flight work has settled. Requests with an old revision return `409 STALE_SESSION`. An old tab cannot stop the new owner. Unscoped compatibility requests are accepted only before the first claim. Use `/api/session/stop` for browser pause/reset so generation and transport are cancelled together.

Native start, resume, and transition requests independently refresh the local OAuth check. Native pattern updates and manual triggers reuse a result for up to 15 seconds to keep repeated hits responsive. Failed checks reject playback; pause, reset, and session stop remain available even after sign-out. Auth probes observe the request's cancellation signal, and a late successful probe cannot execute a stopped native request. `GET /api/status` is also cancelled when its HTTP request disconnects. Application shutdown closes all sessions, aborts active Codex children, clears native output, and closes the local server.

`startAt` is the Unix timestamp in milliseconds for audible cycle zero or the resumed cycle. Native start installs all eight patterns under `filterWhen (>= id*2)` gates before moving the Tidal clock. Tidal then owns exact two-cycle entrances and indefinite looping. The 700 ms preparation lead accounts for Tidal's 50 ms OSC target compensation, which Tidal subtracts from outgoing timestamps; the scheduler looks ahead 300 ms. Browser animation and shadow synthesis may schedule against `startAt`; device buffering can still cause a small output offset. Pause captures the current cycle and hushes; resume restores the buffered score at that phase. New layers need no HTTP request at the moment they enter. Native pause waits for SuperDirt's transport acknowledgement after muting and draining pending events.

Genre transitions use two independent Tidal streams with Link disabled. Each owns eight SuperDirt orbits and a separate stereo bus. The incoming complete score begins at cycle zero on its own tempo while the previous score continues at its original tempo. The SuperCollider mixer performs an equal-power crossfade at the returned `startAt`. After the fade, the previous clock hushes and its notes drain before that deck can be reused. A transition already in progress returns `409 TRANSITION_BUSY`. Pausing during an acknowledged fade selects the incoming score, mutes both decks, and preserves the incoming cycle. Resume accepts authoritative browser loops, BPM, cycle, and `fullScore`; this also resolves a pause racing an unacknowledged transition. `fullScore:true` restores all eight layers immediately, while false preserves two-cycle entry gates. Reset clears both decks.

Manual triggers use the earliest event step in the selected loop, including every simultaneous chord note. Each note retains its velocity and duration, capped at 1.2 seconds for the manual hit. Every HTTP request creates independent synth nodes; onsets at the same corner are spaced by at least 35 ms so three rapid clicks produce three distinct attacks while their tails may overlap. Chord notes share one onset. A dedicated seventeenth orbit routes hits to the master mixer. Triggers require active playback and do not alter either deck's clock. Pause and reset clear this orbit, its tails, and scheduled hits along with both score decks. The optional `previous` composition on `/api/compose` supplies validated symbolic genre, tempo, key, timbre, and note context so Codex can prepare a cohesive next genre before the gesture happens.

Errors have `{error,message}` with an HTTP status. Native mode is opt-in and missing dependencies return `503 TIDAL_UNAVAILABLE`. Only HTTP origins on loopback ports 5173, 4173, and 4318 are allowed by default. `SCC_ORIGIN` permits one explicit additional origin. POST requests must be JSON, and request size is capped at 128 KB.

## Native TidalCycles

The native path requires GHC/GHCi with the `tidal` Haskell package, SuperCollider, SuperDirt, Vowel, and Dirt-Samples. `native/BootTidal.hs` targets current Tidal's `Sound.Tidal.Boot` module. A custom `TIDAL_BOOT_FILE` must define the standard Tidal aliases and print `__SCC_TIDAL_READY__` after successfully booting.

Start SuperCollider with `sclang native/superdirt.scd`, using the proper include paths when SuperDirt/Vowel are local checkouts. Samples default to `.runtime/Dirt-Samples/*`, relative to the repository; `SCC_SAMPLE_PATH` overrides the sample glob. The startup file creates sixteen deck orbits plus one manual-hit orbit on UDP 57120, then registers a local `/scc/ping` responder **after** sample and synth loading. Readiness therefore checks a running initialized SuperDirt instance, not merely an installed executable. A custom startup must implement the matching `/scc/transport`, `/scc/mix`, `/scc/clear-deck`, and `/scc/hit` handlers too.

`npm run dev:native` launches the configured native runtime and web app together. For manual startup, use `TIDAL_ENABLED=1 npm run dev:browser` after starting SuperDirt. `GHCI_BIN` can point to an explicit GHCi executable, such as `/opt/homebrew/opt/ghc@9.6/bin/ghci`; `GHC_ENVIRONMENT` should point to the absolute `.runtime/tidal.environment` file when using the project package environment. The native Tidal package was validated with GHC 9.6.7 and Tidal 1.10.3. On Homebrew, building Tidal may require `CPATH=/opt/homebrew/opt/libffi/include`, `LIBRARY_PATH=/opt/homebrew/opt/libffi/lib`, and the matching Cabal `--extra-include-dirs` / `--extra-lib-dirs` arguments.

`CODEX_BIN`, `CODEX_MODEL`, `CODEX_TIMEOUT_MS` (10–240 seconds), `SCC_BRIDGE_PORT`, and `TIDAL_BOOT_FILE` are optional server settings. The web proxy expects bridge port 4318 unless its Vite configuration is adjusted too. `SCC_SAMPLE_ROOT` overrides the HTTP sample directory; set `SCC_SAMPLE_PATH` to the matching SuperDirt glob when changing it. Only 17 known sample banks and their valid numeric indices are exposed. Paths are resolved inside the configured root, symlink escapes are rejected, and WAV files are capped at 32 MB. All current whitelisted banks contain WAV files, including uppercase `.WAV` names. Files are sorted in the same order as SuperDirt. The HTTP route explicitly permits the validated `.runtime` ancestor; arbitrary dotfiles cannot be requested.

The native renderer selects actual drum samples from `bd`, `808bd`, `909`, `sd`, `808sd`, `hh`, `808hc`, `808oh`, `cp`, `perc`, `tabla`, `glitch`, `metal`, `sn`, `jazz`, `east`, and `tink`. The ten bundled core-UGen instruments are `sccbass`, `sccchords`, `sccmelody`, `scctexture`, `sccacid`, `sccpluck`, `sccbell`, `sccpad`, `sccorgan`, and `sccfm`. Readiness asserts that all ten instruments and required sample banks loaded. A master DC filter and limiter follow the orbit mix.

The browser fetches the same actual drum WAV assets and uses distinct Web Audio implementations for pitched instruments. Those pitched voices approximate the native instruments. Browser analysis follows its own samples/synthesis, not a recording of SuperCollider output. The owned SuperCollider startup begins muted and receives fenced local control commands. Pause/reset immediately mute the complete output, reject incoming score events, clear scheduled server bundles, and free all 17 orbits. Each transport, mix, cleanup, and hit command carries a monotonic server fence, so late UDP messages and delayed cleanup callbacks cannot undo a newer stop. Tidal commands check their cancellation fence before execution and after acknowledgement; priority stop hushes again after in-flight commands. Resume unmutes the selected deck ahead of its scheduled start. Transport, mix, and hit commands wait for OSC acknowledgements.
